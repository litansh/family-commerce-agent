In production: `lines resolve to products 0/39`, the 39-line basket → HTTP 503 after 59 s. - [ ] **One blank line 400s a whole `/resolve` or `/quote` call, every other line included.** Found by `ops/chaos.mjs` (new — a real family list with a dozen abuse cases mixed in, per the "test cart" line below). `apps/api/src/index.ts`'s `toLines`/`str()` throws `HttpError(400, "lines[i].query is required")` the moment any one line's `query` is empty — this rejects the *entire* batch, not just that line, the opposite of `/resolve`'s own `unresolved`-per-line design above. Reproduced live 2026-09-13: a 3-line request with one blank line among two good ones → HTTP 400 for all three; the same list with the blank line removed → HTTP 200. A family's list can end up with a blank row (a cleared name, a bad paste, voice-to-text) more easily than a barcode nowhere. *api-fixer*
- [ ] **A query with no real words in it resolves to an unrelated real product instead of nothing.** Found by `ops/chaos.mjs`: `POST /resolve` with a single line `{query:"12345"}` (no letters, a bare number — the kind of thing a stray tap or a copy-paste artifact leaves in a list) returns `chosen: {gtin:"7290110455262", name:"לק קריסטל גלו 651 יח", brand:"דניה קוסמטיקס"}` — nail polish, sharing zero words with "12345". Whatever ranks `buildChoice`'s candidates for a query with no meaningful tokens needs a floor: no candidate, not a guessed one, when nothing in the query matches anything in the name. Emoji-only and empty queries correctly resolve to nothing today; a bare number does not. *api-fixer*
- [ ] **A barcode the catalogue lacks, with a name that says so, gets substituted into an unrelated real product server-side — not just in the mobile cart recipe** (see "Rami Levy cart recipe's name fallback" below). Found by `ops/chaos.mjs`: a line `{query:"לא קיים", gtin:"9999999999999"}` (a deliberately absent barcode, name literally "does not exist") survives resolve unresolved as expected, but `/quote` prices it anyway — `storefrontLines["rami-levy-online"]["<lineId>"]` comes back `{productName:"תרד לא שטוף יח ( ניוזילנדי )", substituted:true, reason:"לא קיים → תרד לא שטוף יח ( ניוזילנדי )", swapBy:"store"}` (unwashed spinach). `swapBy:"store"` means this is the vendor's own free-text fallback when `quoteBasket` is given an unknown barcode plus a name, passed straight to the family as if Kaniti stood behind it — the head-word/half-the-words rule `PICK_BY_NAME_JS` already enforces client-side for the cart recipe (`apps/mobile/src/lib/stores.ts`) is not applied to this server-side substitution at all. Promise 3 ("no substitute is a different category") and promise 9 both broken by the same gap. Reproduced with a clean 200 response, not a flaky provider minute. *api-fixer*
