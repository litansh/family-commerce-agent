(found them there under "Reported by the owner, 13 September 2026", each already tagged *api-fixer*, none yet on this list — picked up directly since the owner-reported lines come first):
  1. **One blank line 400s a whole `/resolve` or `/quote` call.** `toLines`'s `str(l.query, ...)` threw `HttpError(400)` for the *entire* batch the moment any one line's query was empty. Reproduced by reading the code path directly (a family's list can end up with a blank row — a cleared name, a bad paste, voice-to-text — far more easily than a rejected barcode). Fixed: a blank/non-string query no longer throws, it carries through as `query: ''`; `/resolve` now skips the catalogue call for it and marks it `unresolved` immediately; `buildCompare` leaves it out of what is sent to the vendor (nothing to quote, no reason to risk the vendor choking on an empty query for the whole batch).
  2. **A bare number resolves to an unrelated real product** (`"12345"` → nail polish) and **4. a query for something no store carries does too** (`"מיץ קקטוס קפוא נדיר מהחלל"` → sugar-free candy) — same root cause, confirmed the same fix by the backlog's own note ("likely the same fix, not two"): `buildChoice` had no floor requiring a candidate's name to share anything with the query once its numeric-constraint filter (`nameSatisfiesQuery`) had nothing to check (no digits in the query) or found nothing (the candidate list was never really about what was typed). Fixed: a new `sharesWordWithQuery` (`packages/domain/src/brand.ts`) requires at least one real word (≥3 chars, the same floor `apps/mobile/src/lib/stores.ts`'s `PICK_BY_NAME_JS` already applies, so "לא" in "לא קיים" does not count) to appear in a candidate's name before it can be chosen at all; `buildChoice` (`packages/domain/src/choice.ts`) applies it before the numeric-constraint narrowing. `packages/domain/test/choice.test.ts` + `brand.test.ts`: 5 new cases (bare number, fictitious query, an unrelated-name pot still correctly resolves when a real word is shared, `sharesWordWithQuery` itself).
  3. **A barcode the catalogue lacks gets server-side quote-time substituted into an unrelated real product** (`{query:"לא קיים", gtin:"999..."}` → "תרד לא שטוף" / unwashed spinach, `swapBy:"store"`) — this is the *vendor's own* free-text fallback (`SuperMcpQuoteProvider`, `services/retailer-connectors/src/supermcp.ts`) when given an unknown barcode + a name; it was passed straight through as a priced line with nothing checked. Fixed: the same `sharesWordWithQuery` floor is applied at the point the vendor's raw `plans[].lines[]` are turned into `QuotedLine`s — a line the vendor itself flagged `substituted` (and that is not its own `chain_equivalent` cross-chain match) is dropped entirely unless the substituted name shares a real word with what was asked. `services/retailer-connectors/test/supermcp.test.ts` (new, 3 cases): the exact "לא קיים" → spinach shape is dropped, a real substitution that does share a word is kept, `chain_equivalent` is never touched by the filter.
  5. **A mixed Hebrew/English line vanishes from `/resolve` without being marked unresolved** (`{query:"חלב milk 3%"}` → `choices: {"<id>": null}`, absent from `unresolved` too). Cause: `/resolve`'s per-line handler only pushed to `unresolved` inside its `catch` block — a line that legitimately resolved to no choice (`buildChoice` returning `undefined`, e.g. the provider's search finding nothing for a mixed-script query) never threw, so it was recorded nowhere a downstream reader (the compare, "every line accounted for") could tell it apart from a line never sent. Fixed: `choices[line.id] = null` is now always paired with `unresolved.push(line.id)`, not only on a caught error.

- [x] **Production 500/503 across quote, search and deals (health run 2026-10-03T03:42Z)** — branch `ops/2026-10-03-api-500-503`, PR opened by the orchestrator. Root cause, from the production log (`logs.yml` run 37094409264) and CloudWatch: SuperMCP answered `Service is busy. Please retry shortly. (code: service_busy)` **60 times in 03:40–03:42**, to `search_products` and `optimize_delivery` alike. Lambda memory was fine (229/512 MB) and no Lambda timed out. `McpClient` retried only `internal_error`, so every busy answer became a 500 (`console.error` → 'internal error') or an unresolved line (`/resolve` logged 22 of 52 lines unresolved, including the typo, mixed-language, טופו and שוקולד lines).
